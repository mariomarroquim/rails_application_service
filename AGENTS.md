# Rails Application Service

Rails Application Service is a Ruby gem that adds service classes (e.g., use cases, features, or commands) to Ruby on Rails web applications.

## Project details

### Commands

- `bin/console`: IRB with the gem loaded.
- `bin/setup`: install dependencies.
- `bundle exec rake install`: install locally.
- `bundle exec rake release`: tag, push, and publish to RubyGems (bump `lib/application_service/version.rb` first).
- `bundle exec rake`: default task, runs specs and then RuboCop.
- `bundle exec rspec --only-failures`: rerun failures (status is kept in `.rspec_status`).
- `bundle exec rspec spec/file:15`: run a single example by file and line.
- `bundle exec rspec`: run the test suite.
- `bundle exec rubocop` (`-a` to autocorrect): lint.

### Architecture

All the behavior lives in `ApplicationService::Base` in `lib/application_service.rb`.

- **Naming:** the gem is published as `rails_application_service`, but the module is `ApplicationService`,
  the require path is `application_service`, and the gemspec is `application_service.gemspec`.
- **ActiveModel only:** `Base` includes `ActiveModel::Model`, so subclasses get keyword-argument initialization (`attr_accessor` attributes) and `validates`.
- **Runtime dependencies:** The only runtime dependency is `activemodel >= 8.0`. The gem does not depend on Rails itself.
- **The `call` contract:** the class method `Base.call(**)` forwards its keyword arguments to `new` to build an instance, returns `false` if `valid?` fails,
  and otherwise returns the result of the instance's `call`.
  The service instance (and its `errors`) is thrown away, so callers get only the return value or `false`.
- **Abstract classes:** `Base` declares itself abstract with `abstract_class!`, and subclasses can do the same.
  Like ActiveRecord's `abstract_class`, the flag is a class instance variable, so it is not inherited.
  Instantiating an abstract class, or calling a subclass without `#call`,
  raises `ApplicationService::NotImplementedError` (a `StandardError`).
- **Specs as subclasses:** specs define small concrete subclasses inline to exercise the base class.

### Constraints

- **Packaging:** the gem ships only git-tracked files, so commit new `lib/` files before releasing.
- **Changes:** record user-facing changes in `CHANGELOG.md`.

## Conventions

- Don't add any new dependencies without asking first.
- Don't remove default comments generated by templates.
- If the code changes, sync both `AGENTS.md` and `README.md` as well.
- Keep lines in MD files under 160 chars long, with natural line breaks.
  No words should be left alone on a line, and no inline code should be split across lines.
- Run `bundle exec rspec` to check for errors before every commit.
- Don't commit or push changes unless explicitly required.
- This project only uses the `main` branch; commit and push to it when required.
